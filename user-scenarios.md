# Пользовательские сценарии

### 1. Регистрация и авторизация пользователей (веб-сервис)

**Регистрация:**
1. Пользователь открывает веб-приложение сервиса.
2. На стартовой странице находит и выбирает опцию перехода к регистрации.
3. Переходит на форму регистрации.
4. Вводит своё имя в соответствующее поле формы.
5. Придумывает и вводит уникальный логин для идентификации в системе.
6. Вводит пароль, удовлетворяющий требованиям безопасности (минимальная длина — 6 символов).
7. При наличии вводит номер телефона для дополнительной связи.
8. Нажимает кнопку отправки формы регистрации.
9. Система проверяет корректность заполнения всех обязательных полей.
10. Система проверяет уникальность указанного логина в базе данных.
11. При успешной проверке система создаёт учётную запись и перенаправляет пользователя на главную страницу.
12. При обнаружении занятого логина система отображает сообщение об ошибке и предлагает выбрать другой логин.

**Авторизация:**
13. Пользователь открывает веб-приложение сервиса.
14. На стартовой странице находит форму входа в систему.
15. Вводит логин, указанный при регистрации.
16. Вводит пароль от учётной записи.
17. Нажимает кнопку входа в систему.
18. Система отправляет запрос на проверку учётных данных на сервер.
19. Сервер выполняет поиск пользователя в базе данных по указанному логину.
20. Сервер сравнивает введённый пароль с хранящимся в базе данных.
21. При успешной проверке система авторизует пользователя и перенаправляет на главную страницу со списком точек выдачи.
22. При неверных данных система отображает сообщение об ошибке и предлагает повторить ввод.

### 2. Аренда зонтов с минимальным числом действий (веб-сервис)

1. Авторизованный пользователь попадает на главную страницу, отображающую список точек выдачи.
2. Система загружает и отображает информацию о всех доступных точках выдачи.
3. Каждая точка выдачи представлена в виде карточки, содержащей название, адрес и количество доступных зонтов.
4. Количество доступных зонтов визуально маркируется цветом: зелёный — зонты есть, красный — зонты закончились.
5. Пользователь выбирает подходящую точку выдачи и нажимает кнопку аренды.
6. Система проверяет, нет ли у пользователя уже активной аренды — сервис допускает только одну аренду на одного пользователя одновременно.
7. Система проверяет наличие доступных зонтов в выбранной точке выдачи.
8. При успешной проверке система создаёт запись об аренде в базе данных и уменьшает счётчик доступных зонтов в выбранной точке на единицу.
9. Система перенаправляет пользователя на экран управления активной арендой с отображением таймера.
10. Если аренда невозможна, система отображает соответствующее сообщение об ошибке.

### 3. Таймер времени аренды зонтов (веб-сервис)

1. После оформления аренды пользователь попадает на экран управления арендой.
2. На экране отображается информация о точке выдачи: название и адрес.
3. Запускается обратный отсчёт таймера, отображаемый крупным шрифтом в формате часы:минуты:секунды.
4. Таймер установлен на фиксированный срок аренды (1 час) и обновляется каждую секунду.
5. Таймер визуально выделен цветом для обеспечения заметности.
6. По истечении отведённого времени на экране появляется предупреждение о необходимости возврата зонта.
7. Пользователь может вернуть зонт досрочно в любой момент, нажав кнопку возврата.
8. При возврате система отправляет запрос на сервер для фиксации завершения аренды.
9. Сервер фиксирует время завершения аренды и увеличивает счётчик доступных зонтов в точке выдачи на единицу.
10. Система отображает сообщение об успешном возврате и перенаправляет пользователя на главную страницу.

### 4. Хранение учетных данных (сервер и база данных)

1. При регистрации данные пользователя (имя, логин, пароль, телефон) передаются на сервер в формате JSON.
2. Сервер сохраняет данные в таблицу базы данных, содержащую информацию о пользователях.
3. Логин пользователя имеет ограничение уникальности — система не допускает создания двух учётных записей с одинаковым логином.
4. Пароль сохраняется в базе данных в незашифрованном виде для упрощения проверки при авторизации.
5. Номер телефона является опциональным полем и может оставаться пустым.
6. Дата создания учётной записи автоматически фиксируется сервером в момент регистрации.
7. При авторизации сервер выполняет запрос к базе данных для извлечения данных пользователя по логину и сравнивает пароли.
8. При обнаружении дублирующего логина сервер возвращает ошибку с описанием проблемы.
9. При сбое соединения между клиентом и сервером клиент отображает сообщение об ошибке подключения.

### 5. Хранение информации о доступных для аренды зонтов (сервер и база данных)

1. Информация о точках выдачи зонтов хранится в отдельной таблице базы данных.
2. Каждая запись точки выдачи содержит название, адрес и счётчик доступных зонтов со значением по умолчанию ноль.
3. Система связывает записи аренд с конкретными точками выдачи через внешние ключи.
4. При создании новой аренды система автоматически уменьшает счётчик доступных зонтов в выбранной точке на единицу.
5. При возврате зонта система автоматически увеличивает счётчик доступных зонтов в соответствующей точке на единицу.
6. Перед каждой арендой система проверяет значение счётчика — аренда запрещена, если счётчик равен нулю.
7. При запросе главной страницы система загружает данные обо всех точках выдачи для отображения пользователю.
8. История всех операций с зонтами (аренда, возврат) сохраняется в таблице аренд с указанием времени начала и завершения.

### 6. Управление профилем и настройками (веб-сервис)

1. Пользователь нажимает на иконку профиля в навигационной панели главного экрана.
2. Переходит на экран профиля, отображающий информацию об учётной записи.
3. На экране отображается имя пользователя, логин и номер телефона.
4. Система загружает актуальные данные профиля с сервера при каждом открытии экрана.
5. В профиле отображается раздел истории аренд, позволяющий просмотреть предыдущие операции.
6. Раздел истории аренд доступен для навигации, но функционал отображения деталей находится в стадии разработки.
7. Пользователь может выйти из учётной записи, нажав кнопку выхода внизу экрана профиля.
8. При нажатии кнопки выхода система показывает диалоговое окно подтверждения выхода.
9. После подтверждения система очищает данные текущей сессии и перенаправляет пользователя на экран входа.

### 7. Адаптивный и доступный интерфейс (веб-сервис)

1. Приложение использует фреймворк Material Design, обеспечивающий адаптивность под различные размеры экранов устройств.
2. Список точек выдачи автоматически прокручивается при превышении количества элементов доступной высотой экрана.
3. Карточки точек выдачи содержат название, адрес и количество доступных зонтов, расположенные вертикально для компактного отображения.
4. Кнопка аренды становится визуально неактивной и недоступной для нажатия, если зонты в выбранной точке отсутствуют.
5. Формы регистрации и входа поддерживают прокрутку содержимого при недостаточном размере экрана для отображения всех элементов.
6. Все поля ввода имеют текстовые метки, позволяющие вспомогательным технологиям корректно озвучить назначение каждого поля.
7. Все интерактивные элементы содержат текстовые описания, читаемые скринридерами.
8. Сообщения об ошибках и предупреждения отображаются в нижней части экрана и озвучиваются вспомогательными технологиями.
9. Диалоговые окна подтверждения действий содержат заголовок, описание и кнопки выбора, обеспечивая понятный интерфейс взаимодействия.
10. Текст таймера отображается крупным шрифтом, обеспечивая хорошую читаемость на любом расстоянии от экрана устройства.
